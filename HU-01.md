# HU-01: Manejar respuesta de login sin usuario

## Origen
- **H-WEB-08** — componente: `web`; estado: Pendiente.
- Evidencia: `web/src/app/models/auth.model.ts:17`; `web/src/app/login/login.component.ts:48`; `web/src/app/services/auth.service.ts:44`; `web/src/app/services/auth.service.ts:60`; `web/src/app/dashboard/dashboard.component.ts:47`.

## Contexto
La matriz indica que `LoginResponse.user` es opcional, pero el flujo acepta una respuesta que contiene token sin usuario. Al guardar esa sesión, `getUser()` puede lanzar una excepción al abrir el dashboard. La matriz deja pendiente definir y validar el tratamiento de la respuesta incompleta.

## Ajustes necesarios
- Definir el contrato esperado para una respuesta de login que incluya token y no incluya usuario.
- Validar la respuesta incompleta antes de guardar o consumir la sesión, evitando la excepción descrita en el dashboard.
- Agregar pruebas para el caso incompleto sin adaptar pruebas para aceptar el fallo actual.

## Criterios de aceptacion
- Una prueba con respuesta de login que contiene token y no contiene usuario verifica que no se guarda como una sesión válida.
- Una prueba del flujo posterior verifica que esa respuesta no provoca una excepción al acceder al dashboard.
- Una prueba de login con una respuesta que incluye usuario verifica el comportamiento conforme al contrato definido para la respuesta válida.

## Evidencia esperada
- Pruebas automatizadas para la respuesta incompleta y para la respuesta válida, con su salida de ejecución.
- Registro del contrato acordado para la respuesta incompleta y del resultado de su validación.
